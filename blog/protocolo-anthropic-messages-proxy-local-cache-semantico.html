1. A Lacuna de Protocolo Entre o Claude Code e a Inferência Local

Apontar um agente de código nativo da Anthropic como o Claude Code para um servidor de inferência local — seja benni-inference-engine, llama.cpp ou vLLM — falha imediatamente na fronteira HTTP se você expõe apenas um endpoint /v1/chat/completions compatível com OpenAI. Mesmo quando servidores locais anunciam uma camada de compatibilidade Anthropic, divergências sutis de protocolo derrubam chamadas de ferramentas, quebram o cálculo de janela de contexto ou travam o streaming.

O protocolo de rede da Anthropic parte de quatro premissas estruturais que não possuem mapeamento 1:1 com o formato OpenAI Chat Completions:

  • Orçamento Pre-flight de Tokens (POST /v1/messages/count_tokens): Antes de enviar turnos pesados com múltiplos arquivos, o Claude Code chama /v1/messages/count_tokens com o payload exato de system, tools e messages para decidir se precisa compactar o histórico. Um 404 ou estimativa imprecisa quebra a compactação automática.
  • Campo system no Topo e Arrays de Blocos Tipados: Ao contrário da string simples ou mensagem role: "system" da OpenAI, a Anthropic envia system no nível raiz como string ou lista de blocos com anotações de cache, e modela o content de cada turno como uma lista polimórfica de blocos text, thinking, tool_use e tool_result.
  • Loops Intercalados de Execução de Ferramentas: Um turno do assistente pode emitir múltiplos blocos tool_use junto com texto de raciocínio, e o turno seguinte do usuário deve retornar blocos tool_result correspondentes vinculados por tool_use_id — algo que servidores OpenAI esperam como mensagens separadas com role: "tool".
  • Ciclo de Vida SSE com Estado: O streaming da Anthropic é uma máquina de estados explícita (message_start → content_block_start → content_block_delta → content_block_stop → message_delta → message_stop), e não apenas deltas sem estado em data: {"choices":[{"delta":...}]}.
Arquitetura de Roteamento Soberano: O Benni-OS/claude-code-router opera em 127.0.0.1 como um proxy de protocolo com latência zero — terminando /v1/messages e /v1/messages/count_tokens, traduzindo grafos de blocos bidirecionalmente para o benni-inference-engine e respondendo prefixos repetidos diretamente via cache semântico em SQLite WAL.

3. Anatomia da Tradução de Protocolo: tool_use, tool_result e count_tokens

Traduzindo system e tools

No schema de requisição da Anthropic, system pode ser uma string simples ou uma lista de objetos {"type": "text", "text": "...", "cache_control": {"type": "ephemeral"}}. O proxy achata todos os blocos de sistema em uma mensagem inicial {"role": "system", "content": "..."} enquanto extrai os limites de cache_control como checkpoints de hash de prefixo para o cache local.

Da mesma forma, cada definição de ferramenta Anthropic ({"name", "description", "input_schema"}) é convertida para o wrapper OpenAI {"type": "function", "function": {"name", "description", "parameters"}}, enquanto tool_choice mapeia {"type": "auto"}, {"type": "any"} (→ "required") e {"type": "tool", "name": "..."} (→ {"type": "function", "function": {"name": "..."}}).

Desmembrando Blocos tool_use e tool_result

O invariante estrutural mais crítico é preservar turnos com múltiplas ferramentas. Uma mensagem assistant da Anthropic pode conter um bloco text e dois blocos tool_use. O roteador empacota o texto em content e converte cada tool_use em uma entrada de tool_calls com json.dumps(block["input"]). No turno seguinte, uma mensagem user contendo blocos tool_result precisa ser explodida em mensagens individuais com role: "tool" indexadas por tool_call_id antes de qualquer bloco textual subsequente do usuário.

Endpoint Local /v1/messages/count_tokens

Em vez de devolver um número fixo fictício — o que faz o Claude Code subutilizar o contexto ou estourar o limite de KV-cache local — o claude-code-router executa uma passagem rápida de tokenização local sobre o system prompt serializado, schemas JSON das ferramentas e blocos de mensagem, retornando {"input_tokens": count} em menos de 1 milissegundo.

4. Tradutor de Protocolo em Python: Requisição e Máquina de Estados SSE

Abaixo está o núcleo bidirecional de tradução em Python utilizado dentro do claude-code-router — cobrindo a conversão de payload Anthropic para OpenAI e a máquina de estados SSE sem bufferização que converte chunks OpenAI de volta em quadros estritos da Anthropic:

import hashlib
import json
from typing import Any, Iterator


def flatten_system_prompt(system: str | list[dict[str, Any]] | None) -> str:
    """Normaliza o campo system da Anthropic (string ou lista de blocos) em texto."""
    if not system:
        return ""
    if isinstance(system, str):
        return system
    return "\n".join(b.get("text", "") for b in system if b.get("type") == "text")


def anthropic_to_openai_request(payload: dict[str, Any]) -> dict[str, Any]:
    """Traduz um payload /v1/messages da Anthropic para /v1/chat/completions OpenAI."""
    oai_messages: list[dict[str, Any]] = []

    sys_text = flatten_system_prompt(payload.get("system"))
    if sys_text:
        oai_messages.append({"role": "system", "content": sys_text})

    for msg in payload.get("messages", []):
        role = msg["role"]
        content = msg["content"]

        if isinstance(content, str):
            oai_messages.append({"role": role, "content": content})
            continue

        text_parts: list[str] = []
        tool_calls: list[dict[str, Any]] = []
        tool_results: list[dict[str, Any]] = []

        for block in content:
            btype = block.get("type")
            if btype == "text":
                text_parts.append(block.get("text", ""))
            elif btype == "tool_use":
                tool_calls.append({
                    "id": block["id"],
                    "type": "function",
                    "function": {
                        "name": block["name"],
                        "arguments": json.dumps(block.get("input", {}), separators=(",", ":")),
                    },
                })
            elif btype == "tool_result":
                raw = block.get("content", "")
                serialized = raw if isinstance(raw, str) else json.dumps(raw)
                tool_results.append({
                    "role": "tool",
                    "tool_call_id": block["tool_use_id"],
                    "content": serialized,
                })

        if role == "assistant":
            oai_messages.append({
                "role": "assistant",
                "content": "\n".join(text_parts) if text_parts else None,
                **({"tool_calls": tool_calls} if tool_calls else {}),
            })
        else:
            # A Anthropic envia tool_result dentro de user; a OpenAI exige role="tool" antes.
            oai_messages.extend(tool_results)
            if text_parts:
                oai_messages.append({"role": "user", "content": "\n".join(text_parts)})

    oai_tools = [
        {
            "type": "function",
            "function": {
                "name": t["name"],
                "description": t.get("description", ""),
                "parameters": t.get("input_schema", {"type": "object", "properties": {}}),
            },
        }
        for t in payload.get("tools", [])
    ]

    return {
        "model": payload["model"],
        "messages": oai_messages,
        "max_tokens": payload.get("max_tokens", 4096),
        "temperature": payload.get("temperature", 0.0),
        "stream": payload.get("stream", False),
        **({"tools": oai_tools} if oai_tools else {}),
    }


def sse_frame(event: str, data: dict[str, Any]) -> str:
    return f"event: {event}\ndata: {json.dumps(data, separators=(',', ':'))}\n\n"


def translate_openai_sse_to_anthropic(
    chunks: Iterator[dict[str, Any]],
    model: str,
    msg_id: str = "msg_local_01",
) -> Iterator[str]:
    """Máquina de estados sem bufferização de deltas OpenAI para quadros SSE Anthropic."""
    yield sse_frame("message_start", {
        "type": "message_start",
        "message": {
            "id": msg_id, "type": "message", "role": "assistant",
            "model": model, "content": [], "stop_reason": None,
            "usage": {"input_tokens": 0, "output_tokens": 0},
        },
    })

    block_idx = -1
    active_type: str | None = None
    saw_tool_calls = False

    for chunk in chunks:
        choice = chunk["choices"][0]
        delta = choice.get("delta", {})

        if delta.get("content"):
            if active_type != "text":
                if block_idx >= 0:
                    yield sse_frame("content_block_stop", {"type": "content_block_stop", "index": block_idx})
                block_idx += 1
                active_type = "text"
                yield sse_frame("content_block_start", {
                    "type": "content_block_start", "index": block_idx,
                    "content_block": {"type": "text", "text": ""},
                })
            yield sse_frame("content_block_delta", {
                "type": "content_block_delta", "index": block_idx,
                "delta": {"type": "text_delta", "text": delta["content"]},
            })

        for tc in delta.get("tool_calls", []):
            saw_tool_calls = True
            if tc.get("id"):
                if block_idx >= 0:
                    yield sse_frame("content_block_stop", {"type": "content_block_stop", "index": block_idx})
                block_idx += 1
                active_type = "tool_use"
                yield sse_frame("content_block_start", {
                    "type": "content_block_start", "index": block_idx,
                    "content_block": {
                        "type": "tool_use", "id": tc["id"],
                        "name": tc["function"]["name"], "input": {},
                    },
                })
            args_part = tc.get("function", {}).get("arguments")
            if args_part:
                yield sse_frame("content_block_delta", {
                    "type": "content_block_delta", "index": block_idx,
                    "delta": {"type": "input_json_delta", "partial_json": args_part},
                })

        if choice.get("finish_reason"):
            if block_idx >= 0:
                yield sse_frame("content_block_stop", {"type": "content_block_stop", "index": block_idx})
            stop_reason = "tool_use" if saw_tool_calls else "end_turn"
            yield sse_frame("message_delta", {
                "type": "message_delta",
                "delta": {"stop_reason": stop_reason, "stop_sequence": None},
                "usage": {"output_tokens": chunk.get("usage", {}).get("completion_tokens", 0)},
            })
            yield sse_frame("message_stop", {"type": "message_stop"})
            break

5. Cache Semântico de Prefixos com SQLite WAL

Loops agênticos de programação são altamente repetitivos no nível de prefixo: as instruções do CLAUDE.md, mais de 20 schemas de ferramentas MCP e os turnos iniciais de exploração do repositório permanecem idênticos byte a byte ao longo de dezenas de requisições. Mesmo quando o prompt final do usuário muda levemente (como reexecutar uma verificação de lint ou repetir uma pergunta diagnóstica), o hash do prefixo e o embedding semântico permanecem praticamente idênticos.

O Benni-OS/claude-code-router combina hashing exato SHA-256 de prefixos com um armazenamento local em SQLite Write-Ahead Logging (WAL):

  • Leituras Concorrentes Sem Bloqueio: Habilitar PRAGMA journal_mode=WAL; e PRAGMA synchronous=NORMAL; permite que múltiplos subagentes em paralelo leiam o cache simultaneamente sem travamentos por lock de escrita.
  • Busca em Dois Níveis: Primeiro, uma consulta indexada O(1) em prefix_sha256 (calculado sobre system + tools + prefix_messages canonicalizados até o último ponto de quebra cache_control). Segundo, para consultas determinísticas com temperatura zero, uma checagem de similaridade por cosseno normalizada contra embeddings locais quantizados do prompt final.
  • Alinhamento de KV-Cache no benni-inference-engine: Mesmo em um cache miss semântico, o roteador repassa o prefix_sha256 correspondente como cabeçalho de dica de slot ao benni-inference-engine, maximizando o reaproveitamento de KV-cache na GPU entre slots locais de llama.cpp / vLLM.

Perguntas Frequentes

Por que clientes Anthropic como o Claude Code não falam diretamente com servidores locais compatíveis com OpenAI?
O Claude Code utiliza o protocolo /v1/messages e /v1/messages/count_tokens da Anthropic, que emprega arrays system no topo do payload, blocos de conteúdo tipados (text, thinking, tool_use, tool_result) e um ciclo de vida com estado em Server-Sent Events (SSE). Servidores locais compatíveis com OpenAI esperam /v1/chat/completions com mensagens de sistema dentro de messages[], argumentos de tool_calls serializados como string e deltas sem estado.
Como o claude-code-router trata /v1/messages/count_tokens localmente?
O Claude Code dispara requisições pre-flight POST /v1/messages/count_tokens para orçar a janela de contexto antes de enviar turnos. O claude-code-router intercepta esse endpoint localmente, serializa system prompts, schemas de ferramentas e blocos de mensagem em texto canônico e calcula a contagem determinística de tokens em menos de 1 milissegundo sem consultar nenhuma API na nuvem.
Como a tradução de streaming SSE preserva blocos tool_use sem bufferizar toda a resposta?
O claude-code-router mantém uma máquina de estados finita por requisição que rastreia o content_block_index ativo. Conforme chegam chunks delta no formato OpenAI do benni-inference-engine, deltas de texto emitem eventos text_delta no índice 0, enquanto chunks incrementais de tool_calls abrem um bloco tool_use via content_block_start e transmitem JSON parcial como quadros input_json_delta até que finish_reason dispare content_block_stop e message_stop.
Por que usar SQLite WAL para cache semântico de prefixos em um roteador proxy local?
O SQLite em modo Write-Ahead Logging (WAL) oferece um cache embutido de arquivo único, sem daemon externo, com leituras concorrentes não bloqueantes e consultas atômicas por hash de prefixo. Ao calcular hashes de system prompts normalizados, schemas de ferramentas e prefixos estáveis de conversa junto aos pontos de quebra cache_control, o claude-code-router responde turnos repetidos e pre-flight em menos de 1 ms com auditabilidade local completa.
