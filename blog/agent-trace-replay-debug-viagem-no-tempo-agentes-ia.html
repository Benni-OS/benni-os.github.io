Debug com Viagem no Tempo para Agentes de IA: Replay Determinístico de Trajetórias e Bifurcação Contrafactual com Custo Zero de Tokens

Por que depurar agentes de IA estocásticos reexecutando loops de LLM ao vivo queima milhares de tokens e mascara a causa-raiz, e como o Benni-OS/agent-trace-replay transforma cada execução em um ledger imutável, retrocedível e ramificável.

1. A Armadilha do Debug Estocástico

Todo engenheiro que já colocou um agente autônomo multi-step em produção conhece a frustração do Loop Heisenbug. O agente executa 18 chamadas de ferramentas, altera três arquivos, interpreta mal uma resposta truncada de API no passo 14 e alucina um rollback destrutivo no passo 17.

Ao tentar reproduzir a falha com ferramentas tradicionais de observabilidade, você bate em três paredes:

  • Reexecução ao Vivo é Não-Determinística: Chamar o LLM novamente com o mesmo prompt inicial gera um fluxo de tokens ligeiramente diferente já no passo 3, desviando a trajetória antes mesmo de alcançar o passo 14.
  • Logs Passivos Não Retrocedem Estado: Dashboards de telemetria JSON mostram o que aconteceu após o crash, mas não reidratam o runtime Python, os stubs de ferramentas e o estado de arquivos no passo 13 para testar uma correção.
  • Queima de Tokens e Latência: Rodar novamente uma trajetória de 25 passos 10 vezes enquanto ajusta um parser ou guardrail consome centenas de milhares de tokens e desperdiça minutos por iteração.
Tese Central: Na engenharia de sistemas clássica, depuradores reversíveis como o rr resolveram bugs não-determinísticos gravando entradas não-determinísticas uma única vez para reproduzi-las de forma determinística para sempre. O Benni-OS/agent-trace-replay traz exatamente essa arquitetura de primeiros princípios para trajetórias de agentes de IA.

2. Arquitetura: Frames Endereçados por Conteúdo & Replay

Em vez de tratar a execução do agente como um loop HTTP efêmero, o agent-trace-replay encapsula tanto a fronteira do LLM quanto a fronteira de Ferramentas com um gravador determinístico de frames. Cada passo gera um TrajectoryFrame imutável selado por uma cadeia de hashes SHA-256 ligada ao frame anterior.

flowchart LR A["Execução ao Vivo\n(Passos 0..N)"] -->|"Grava I/O de LLM + Tools"| B["Ledger Imutável de Traço\n(Cadeia SHA-256)"] B -->|"Replay Custo Zero"| C["Motor de Replay Offline\n(< 2ms por trajetória)"] B -->|"Retroceder ao Passo k"| D["Bifurcação Contrafactual\n(Mutar Tool / Prompt)"] D -->|"Retomar de k+1"| E["Novo Ramo de Execução\n(Diff & Gate de Regressão)"] C -->|"Validar Invariantes"| F["CI/CD Pass / Fail\n(0 Tokens na Nuvem)"]

Repare na separação arquitetural: os passos 0..k são servidos diretamente do ledger gravado com zero chamadas de rede e custo zero de tokens. Somente quando você dispara explicitamente uma bifurcação contrafactual no passo k — por exemplo, injetando um retorno corrigido de ferramenta ou um novo guardrail — a execução diverge para um novo ramo.

3. Anatomia de um Frame Determinístico & Motor de Replay

Abaixo está o núcleo Python que alimenta o agent-trace-replay. Cada frame calcula o hash do prompt normalizado, parâmetros do modelo, saída da ferramenta e hash pai, garantindo integridade criptográfica e alinhamento exato no replay.

import hashlib
import json
from dataclasses import dataclass
from typing import Any, Callable, Dict, List


@dataclass(frozen=True)
class TrajectoryFrame:
    step: int
    kind: str  # "llm_call" | "tool_call" | "state_checkpoint"
    input_payload: Dict[str, Any]
    output_payload: Dict[str, Any]
    parent_hash: str
    frame_hash: str = ""

    @staticmethod
    def compute_hash(
        step: int,
        kind: str,
        input_payload: Dict[str, Any],
        output_payload: Dict[str, Any],
        parent_hash: str,
    ) -> str:
        canonical = json.dumps(
            {
                "step": step,
                "kind": kind,
                "input": input_payload,
                "output": output_payload,
                "parent": parent_hash,
            },
            sort_keys=True,
            separators=(",", ":"),
        )
        return hashlib.sha256(canonical.encode("utf-8")).hexdigest()


class ReplayEngine:
    """Motor de replay determinístico e bifurcação contrafactual com custo zero."""

    def __init__(self, frames: List[TrajectoryFrame]):
        self.frames = frames
        self._verify_chain()

    def _verify_chain(self) -> None:
        expected_parent = "GENESIS"
        for frame in self.frames:
            recomputed = TrajectoryFrame.compute_hash(
                frame.step,
                frame.kind,
                frame.input_payload,
                frame.output_payload,
                expected_parent,
            )
            if frame.parent_hash != expected_parent or frame.frame_hash != recomputed:
                raise ValueError(f"Violação de integridade no passo {frame.step}")
            expected_parent = frame.frame_hash

    def replay_until(self, target_step: int) -> List[TrajectoryFrame]:
        """Reproduz os passos 0..target_step localmente com custo 0 de tokens."""
        return [f for f in self.frames if f.step <= target_step]

    def fork_at(
        self,
        fork_step: int,
        mutator: Callable[[Dict[str, Any]], Dict[str, Any]],
        continuation_fn: Callable[[List[TrajectoryFrame]], TrajectoryFrame],
    ) -> List[TrajectoryFrame]:
        """
        Retrocede até fork_step, aplica mutação contrafactual na saída
        e executa somente a partir de fork_step + 1.
        """
        prefix = self.replay_until(fork_step - 1)
        base_frame = self.frames[fork_step]
        mutated_output = mutator(dict(base_frame.output_payload))
        parent = prefix[-1].frame_hash if prefix else "GENESIS"

        forked_hash = TrajectoryFrame.compute_hash(
            base_frame.step,
            base_frame.kind,
            base_frame.input_payload,
            mutated_output,
            parent,
        )
        forked_frame = TrajectoryFrame(
            step=base_frame.step,
            kind=base_frame.kind,
            input_payload=base_frame.input_payload,
            output_payload=mutated_output,
            parent_hash=parent,
            frame_hash=forked_hash,
        )
        branch = prefix + [forked_frame]
        next_frame = continuation_fn(branch)
        return branch + [next_frame]

4. Bifurcação Contrafactual na Prática

Considere um incidente real: seu agente de código chama read_file em um arquivo de configuração de 1.200 linhas, recebe um buffer truncado, interpreta mal o schema e gera uma migração quebrada no passo 15.

Com o agent-trace-replay, você não reexecuta os passos 0–13 contra GPT-4o ou Claude:

  1. Carregue o Traço de Produção: Baixe o artefato assinado .trace.jsonl do bucket de incidentes.
  2. Retroceda ao Passo 14: Reproduza os passos 0–13 em 0.8 ms usando frames em cache local (0 tokens).
  3. Injete a Mutação Contrafactual: Corrija a saída da tool read_file no passo 14 para incluir o cabeçalho completo do schema, ou teste um guardrail mais rígido.
  4. Trave como Teste de Regressão: Exporte o diff da trajetória como uma fixture determinística de pytest para que essa classe de falha nunca mais reapareça no CI/CD.

6. Integrando Viagem no Tempo no seu Pipeline de CI/CD

Todo bug de produção vira um teste de regressão permanente com custo zero. Em vez de torcer para que um ajuste no prompt tenha resolvido o caso de borda, seu runner de CI valida a transição de estado exata:

def test_migration_agent_handles_truncated_schema():
    engine = ReplayEngine.from_jsonl("fixtures/incident_step14_truncation.trace.jsonl")

    # Reproduz passos 0..13 com custo zero de tokens e valida invariantes
    prefix = engine.replay_until(13)
    assert len(prefix) == 14
    assert prefix[-1].kind == "tool_call"

    # Bifurca no passo 14 com metadados corrigidos da ferramenta
    forked_branch = engine.fork_at(
        fork_step=14,
        mutator=lambda out: {**out, "truncated": False, "schema_version": "v2"},
        continuation_fn=run_local_guardrail_check,
    )
    assert forked_branch[-1].output_payload["safe_to_migrate"] is True

Perguntas Frequentes (FAQ)

Como o agent-trace-replay atinge custo zero de tokens durante o debug?
Durante a execução inicial, o agent-trace-replay grava cada par de requisição/resposta de LLM, invocação de ferramenta e snapshot de estado em um ledger endereçado por conteúdo. Replays subsequentes servem os frames gravados direto do disco local em menos de um milissegundo, sem chamar nenhuma API de LLM na nuvem ou local.
O que é bifurcação contrafactual (counterfactual forking) no debug de agentes?
A bifurcação contrafactual permite retroceder uma trajetória até um passo exato k, alterar uma única variável — como o retorno de uma ferramenta, uma restrição de system prompt ou um parâmetro — e retomar a execução apenas do passo k+1 em diante, mantendo os passos 0..k deterministicamente travados.
Qual a diferença entre o agent-trace-replay e plataformas de observabilidade como LangSmith ou Arize?
Ferramentas tradicionais de observabilidade são coletores passivos de telemetria: elas registram JSONs para inspeção visual, mas exigem reexecutar todo o loop ao vivo do agente para testar uma correção. O agent-trace-replay é um motor de execução ativo com replay determinístico, verificação por hash de estado e checkpoints ramificáveis.
Posso usar o agent-trace-replay em pipelines de regressão CI/CD offline?
Sim. Trajetórias gravadas são compiladas em fixtures determinísticas de pytest. Seu pipeline de CI pode reproduzir centenas de incidentes multi-step offline em segundos, garantindo que novos parsers ou guardrails capturem falhas históricas sem gastar um único token de API.
