Orquestrando Swarms Paralelos no Claude Code Sem Caos de Merge: Git Worktrees, Leases de Arquivos e Blackboard MCP Compartilhado

Por que abrir quatro terminais paralelos do Claude Code resulta em sobrescrita silenciosa de arquivos, conflitos de merge, trabalho duplicado e faturas fora de controle — e como o Benni-OS/claude-code-swarm coordena workers paralelos com sandboxes git worktree isolados, leases em SQLite3 WAL no hook PreToolUse, blackboard MCP compartilhado, tetos globais em USD e portões AST pré-merge.

1. A Ilusão Multi-Terminal: Por Que o Paralelismo Ingênuo Falha

Todo usuário avançado eventualmente esbarra na mesma parede de escala: se uma sessão do Claude Code é rápida, abrir quatro abas de terminal no mesmo repositório deveria ser quatro vezes mais rápido. Na prática, agentes de codificação paralelos sem coordenação se comportam como quatro desenvolvedores editando o mesmo diretório sem travas, sem comunicação e sem orçamento compartilhado.

Em poucos minutos, o paralelismo ingênuo colapsa em quatro modos de falha previsíveis:

  • Sobrescrita Silenciosa de Arquivos: O Worker A lê src/auth.py, o Worker B reescreve o arquivo e a chamada seguinte de Edit ou Write do Worker A apaga o patch do Worker B sem nenhum aviso.
  • Caos de Merge e Colisões de Index Lock: Mesmo criando branches manualmente, dois workers tocando os mesmos módulos centrais geram conflitos de merge complexos e contenção em .git/index.lock.
  • Trabalho Duplicado e Drift de Spec: Sem um estado compartilhado de tarefas, múltiplos terminais refatoram o mesmo helper de forma independente ou implementam assinaturas de API incompatíveis.
  • Explosão de Tokens em Múltiplos Terminais: Quatro agentes presos em loops concorrentes de teste-e-correção multiplicam a queima de API por 4× — sem nenhum circuit breaker global em USD entre os terminais.
Princípio Arquitetural Central: Paralelismo sem exclusão mútua é apenas condição de corrida distribuída. O Benni-OS/claude-code-swarm transforma processos independentes do Claude Code em um swarm determinístico usando sandboxes git worktree isolados, leases de arquivos em SQLite3 WAL aplicados no PreToolUse, blackboard MCP compartilhado, tetos globais em USD e portões AST pré-merge.

2. Arquitetura do Swarm: Worktrees, Leases WAL e Blackboard MCP

Em vez de deixar agentes competirem dentro de um único diretório ou coordenarem via arquivos markdown frágeis, o claude-code-swarm separa isolamento de sistema de arquivos, controle de concorrência e coordenação de tarefas em três camadas determinísticas:

flowchart TD M["Blackboard MCP Compartilhado<br/>(Claims, Dependências, Contratos)"] -->|"Atribuir Tarefa"| W1["Worker 1 (git worktree: swarm/w1)"] M -->|"Atribuir Tarefa"| W2["Worker 2 (git worktree: swarm/w2)"] W1 -->|"PreToolUse (< 1ms)"| L["Coordenador SQLite3 WAL<br/>Leases de Arquivos + Ledger Global USD"] W2 -->|"PreToolUse (< 1ms)"| L L -->|"Lease Ocupado / Teto Atingido"| X["Exit 2: Bloqueado Deterministicamente"] L -->|"Lease Concedido + Orçamento OK"| E["Edição e Testes Isolados no Worktree"] E -->|"Concluído"| G["Portão AST e Lint Pré-Merge"] G -->|"Erro de Sintaxe / Stub"| E G -->|"Verificado Limpo"| R["Fast-Forward / Rebase Atômico para main"]

Cada worker recebe seu próprio diretório físico via git worktree, sua própria branch e seu próprio estado de build/testes — enquanto compartilha um único banco SQLite3 local em modo Write-Ahead Logging (WAL) e um servidor unificado de blackboard MCP.

3. Os Cinco Primitivos Determinísticos do claude-code-swarm

1. Workers Isolados em git worktree

Ao instanciar um swarm de N workers, o claude-code-swarm provisiona N checkouts dedicados de git worktree em .swarm/worktrees/<worker_id>, cada um vinculado a uma feature branch limpa. Os workers nunca compartilham árvore de trabalho, nunca disputam .git/index.lock e rodam suítes de testes isoladas em paralelo.

2. Leases de Arquivos em SQLite3 WAL nos Hooks PreToolUse

Worktrees isolam diretórios, mas se o Worker 1 e o Worker 2 reescreverem src/router.py em branches separadas, você ainda enfrentará um conflito de merge doloroso. Antes que qualquer ferramenta Edit, Write ou Bash mutante execute, o hook PreToolUse consulta a tabela compartilhada de leases em SQLite3 WAL usando BEGIN IMMEDIATE:

  • Se o caminho alvo estiver livre (ou já sob lease do worker_id solicitante), o lease é adquirido ou renovado atomicamente com TTL.
  • Se outro worker ativo detiver o lease, o hook retorna código de saída 2 informando o ID do detentor e a tarefa ativa — forçando o worker bloqueado a reivindicar outra tarefa no blackboard MCP em vez de gerar conflito de merge.

3. Blackboard de Tarefas MCP Compartilhado

Cada worker se conecta ao servidor MCP do swarm (claude mcp add swarm-blackboard). O blackboard expõe ferramentas determinísticas para listar tarefas disponíveis, reivindicar atomicamente um ID de tarefa, publicar contratos de interface (como novos tipos TypeScript ou payloads REST) para workers dependentes e sinalizar conclusão para merge.

4. Tetos Globais em USD para Todo o Swarm

Orçamentos por terminal não resolvem quando quatro terminais queimam $5 cada em um loop travado de tentativas. O hook PostToolUse de cada worker registra deltas de tokens no mesmo ledger em SQLite3 WAL. Antes que qualquer worker execute a próxima chamada de ferramenta, o PreToolUse verifica SUM(cost_usd) em todo o swarm. No instante em que o gasto global atinge max_swarm_usd, todos os workers disparam o circuit breaker simultaneamente.

5. Portões AST Pré-Merge

Passar nos testes unitários locais do worker não basta para entrar na main. Antes que o coordenador mescle qualquer branch de git worktree, um portão AST determinístico analisa todos os arquivos modificados para rejeitar erros de sintaxe, marcadores de conflito pendentes, stubs com TODO/NotImplementedError e imports quebrados — garantindo que a main nunca receba código inacabado.

4. Configurando o Swarm no .claude/settings.json

Subir um swarm coordenado exige apenas registrar o blackboard MCP compartilhado e conectar os hooks determinísticos de lease e orçamento no .claude/settings.json:

# Instalar e inicializar um swarm com 3 workers em git worktrees isolados
pip install claude-code-swarm
claude-swarm init --workers 3 --max-swarm-usd 6.00 --lease-ttl 300

# Registrar o Blackboard de Tarefas MCP compartilhado
claude mcp add swarm-blackboard -- claude-swarm mcp-serve

5. Por Dentro do Hook de Lease SQLite3 WAL e Teto Global

Abaixo está o núcleo atômico de enforcement de leases e orçamento executado em menos de um milissegundo dentro do PreToolUse. Como o SQLite3 roda em modo WAL com BEGIN IMMEDIATE, workers concorrentes nunca corrompem o estado nem atropelam uns aos outros:

import json
import sqlite3
import sys
import time
from pathlib import Path

DB_PATH = Path(".swarm/coordinator.db")


def enforce_lease_and_budget(
    worker_id: str,
    target_path: str | None,
    max_swarm_usd: float = 6.00,
    ttl_sec: int = 300,
) -> tuple[int, str]:
    now = time.time()
    conn = sqlite3.connect(DB_PATH, timeout=5.0, isolation_level=None)
    conn.execute("PRAGMA journal_mode=WAL;")
    try:
        conn.execute("BEGIN IMMEDIATE;")

        # 1. Circuit Breaker FinOps Global do Swarm
        row = conn.execute("SELECT COALESCE(SUM(cost_usd), 0.0) FROM spend_ledger").fetchone()
        total_usd = float(row[0])
        if total_usd >= max_swarm_usd:
            conn.execute("ROLLBACK;")
            return 2, f"SWARM_BUDGET_CAP: Gasto global ${total_usd:.4f} >= teto ${max_swarm_usd:.2f}."

        # 2. Verificação Atômica de Lease de Arquivo (se a ferramenta altera um caminho)
        if target_path:
            conn.execute("DELETE FROM file_leases WHERE expires_at < ?", (now,))
            holder = conn.execute(
                "SELECT worker_id FROM file_leases WHERE file_path = ?",
                (target_path,),
            ).fetchone()

            if holder and holder[0] != worker_id:
                conn.execute("ROLLBACK;")
                return 2, (
                    f"FILE_LEASE_CONFLICT: '{target_path}' está sob lease de '{holder[0]}'. "
                    "Reivindique outra tarefa no blackboard MCP."
                )

            conn.execute(
                """
                INSERT INTO file_leases (file_path, worker_id, expires_at)
                VALUES (?, ?, ?)
                ON CONFLICT(file_path) DO UPDATE SET
                    worker_id = excluded.worker_id,
                    expires_at = excluded.expires_at
                """,
                (target_path, worker_id, now + ttl_sec),
            )

        conn.execute("COMMIT;")
        return 0, json.dumps({"decision": "allow", "worker_id": worker_id, "global_usd": total_usd})
    finally:
        conn.close()


if __name__ == "__main__":
    payload = json.load(sys.stdin)
    worker = payload.get("worker_id", "worker-1")
    file_path = payload.get("tool_input", {}).get("file_path")
    code, msg = enforce_lease_and_budget(worker, file_path)
    if code != 0:
        sys.stderr.write(msg + "\n")
    sys.exit(code)

Perguntas Frequentes

Por que terminais paralelos do Claude Code sobrescrevem os arquivos uns dos outros?
Quando múltiplas instâncias do Claude Code compartilham a mesma árvore de trabalho, elas operam nos mesmos caminhos de arquivo simultaneamente sem exclusão mútua. O Worker A lê um arquivo, o Worker B o reescreve e a chamada Edit ou Write seguinte do Worker A apaga silenciosamente o trabalho do Worker B ou gera travas no índice do Git.
Como os leases em SQLite3 WAL no PreToolUse evitam colisões de edição?
Mesmo com checkouts isolados de git worktree, dois workers editando o mesmo caminho lógico de arquivo em branches diferentes geram conflitos severos de merge. O claude-code-swarm armazena leases por caminho em um banco SQLite3 compartilhado em modo WAL. Antes de qualquer Edit ou Write executar, o hook PreToolUse tenta adquirir o lease atomicamente; se outro worker ativo detiver o lease, ele retorna código 2 e redireciona o agente.
Qual é o papel do blackboard de tarefas MCP compartilhado?
O blackboard MCP oferece a cada worker uma fonte única e atômica de verdade para reivindicação de tarefas, grafos de dependência, heartbeats e artefatos concluídos. Em vez de duplicar trabalho entre terminais, os workers reivindicam tarefas livres via MCP, publicam contratos de interface para tarefas dependentes e liberam os leases ao concluir.
Como tetos globais em USD e portões AST pré-merge protegem a produção?
O consumo de tokens e USD de cada worker é consolidado no ledger compartilhado em SQLite3 WAL; assim que o teto global do swarm é atingido, o PreToolUse dispara o circuit breaker em todos os terminais ao mesmo tempo. Antes que a branch de qualquer git worktree seja mesclada na main, um portão AST valida sintaxe, imports e ausência de stubs com placeholders de forma determinística.
